# Editing in every player (Windows + Android) - approved design (Lead, 02-10)

Owner rules: no split listen/edit; Windows and Android do the same no-toolchain edits; Studio toolchain on Windows unlocks the
rest; .abook vs .abookproj = one format, two extents (like .psd/.psb); "Lưu" keeps type, "Lưu thành…" offers both.
Hash-locked files (abook.quality_policy.QUALITY_IMPLEMENTATION_FILES, incl. listener_overrides.py, database.py) are only CALLED.

Edit classes: L = book-layer edit, applies at once, no toolchain. W = wish, recorded anywhere (overrides.json entry shape),
applied by a Studio run. T = needs toolchain (explain, never hide).

| Edit (server.py route) | Class | Stored today |
|---|---|---|
| Book title (:1700) | L | studio_title.json |
| Cover (:2063/:2082) | L | cover.jpg + cover.json |
| Character display name (:1636) | L | names.json (baked into cast/scripts at pack) |
| Chapter titles | L new | derived from SQLite (store.py:246) |
| Music on/off/level/silence/ban (:1807) | L | music_overrides.json / music_plan.json; .abook has baked cues |
| Music swap/re-pick (:798,:838) | L (desktop first; phone later = TS port of music_select) | same |
| Review ok (:2045) | L | reviews.json |
| Pronunciation (:1898) | W | overrides.json |
| Who says this line (:1952), merge (:1607) | W | overrides.json speakers + aliases.json |
| Line kind/emotion/spoken text (:1995) | W | overrides.json lines |
| Voice/gender (:2022) | W | overrides.json voices |
| Retake (:1653) | W | overrides.json retakes |
| Pending list/withdraw (:1567,:1575) | W mgmt | store.py:401-436 |
| Work inbox/casting/name readings | read-only views; phone via views/ snapshot | SQLite |
| Reading preview, start/stop, new book, redo | T | - |

Architecture:
- /api/app (and Android local equivalent) returns capabilities {toolchain, workshop, link}. UI gates by these.
- With a desktop workshop: existing sidecars are truth. Without (any .abook; .abookproj on phone / no-Studio Windows):
  `edits.json` in the book folder holds L edits + wishes; readers overlay it (Python abook/webui/book_edits.py used by
  packages.listen/cast/script; Kotlin BookEdits.kt used by LibraryPlugin). Book layer never modified in place.
- fold(): Studio machine replays edits.json through existing writers (names.set_name, store.set_display_title,
  listener_overrides.request_*, music_plan.write_overrides), re-stamping requested_at (phone clock skew), then clears it.
- Phone: api() (api.ts:313) gets a pluggable transport; on Android -> EbookLibrary.studio({method,path,body}) ->
  LocalStudio.kt implementing the L/W subset with the same JSON. React Studio screens reused.
- Synced books (Store.computerBooks) push edits.json to POST /sync/v1/books/<id>/edits: L folds; wishes go to an approval
  inbox unless device has remoteStudio permission. Stranger files: producer opening an edited .abook (fingerprints
  recognise own project) gets "N thay đổi - áp vào dự án?".
- Format: book layer + edit layer (edits.json, edits/cover.jpg) = v4 only when edits exist. .abookproj = book layer +
  project.json + project/ + sources/ + views/. .abook rejects project/ sources/ views/. edits.json carries no device names.
  Script segments gain stableId + textSha256 (additive). bookfile.repack(folder,out). extract() merges local edits.json.
  projectfile v2: book layer via bookfile helpers, MP3/WAV stored once (aliases), views/*.json snapshots, same-project fold
  on open instead of duplicating.
- Kotlin: BookDocument reader (both mimetypes), BookDocumentWriter (ZipOutputStream; mimetype first stored; stored
  MP3/WAV with CRC). Phone copies project/ sources/ byte-for-byte, never opens project.sqlite3.
- .abook -> .abookproj = marker project.json {"workshop":"pending"} (+ optional sources/); Studio machine offers
  "Dựng xưởng" and seeds from cast voice keys, wishes, names. Loses sources, analysis history, per-line WAVs, seeds;
  whole audio re-produced.

Phases: P0 capabilities + stableId/textSha256 + spec v4. P1 L edits on .abook both platforms + edits.json overlay +
merge on re-import + Lưu/Lưu thành .abook v4 + producer fold. P2 wishes + sync edits inbox. P3 .abookproj v2
(dedupe, views/, marker, same-project fold, phone opens/saves). P4 phone music swap, cover web search.
Risks: hash lock; two writers (last-writer-wins per key, conflicts listed at fold, wishes never auto-applied); hashed
entries untouched (cover to edits/); edits.json untrusted (caps, schema); phone storage duplicates audio for .abookproj.

# What P0 + P1 actually built (updated with the implementation, 03-10)

Reference implementation: `abook/webui/book_edits.py` (Python) and `BookEdits.kt`, `LocalStudio.kt`, `BookDocumentWriter.kt`
(Android, `mobile/android/app/src/main/java/vn/abook/player`). Both read the same fixtures, `tests/fixtures/book_edits/`
(generated by `tests/book_edits_fixtures.py`); the Python run of each case is the golden file the Kotlin code must reproduce.

## Capabilities (`ui/src/shared/capabilities.ts`)

`{toolchain, workshop, link}`, per book:

- `toolchain` - Studio is installed and usable on this Windows install. Dev builds (`App.studio is None`): true. Packaged
  app: installed and not outdated. Android: always false.
- `workshop` - the book has a project here (`store.is_project`). Android: always false (the phone never opens a sqlite).
- `link` - the book is a "Trên máy khác" book (streamed from another paired computer, not owned by this device).

Delivered as `GET /api/app` -> `capabilities` (`?book=<id>` fills `workshop`/`link`; without it only `toolchain` means
anything), as `capabilities` on every listen book JSON (`/api/listen/library`, `/api/listen/books/<id>`), and on Android as
`capabilities` on every book the plugin returns + `EbookLibrary.capabilities({id})`. The UI edits a book when
`workshop || !link` (`canEdit`); toolchain-only actions stay visible, disabled, with "cần cài Studio".

## Where an edit lives

| Book | Title | Cover | Character name | Chapter title | Music |
|---|---|---|---|---|---|
| workshop (project) | `studio_title.json` | `cover.jpg` + `cover.json` | `names.json` | `chapter_titles.json` (new; read by `store.chapter_names`) | `music_overrides.json` |
| no workshop (imported .abook / phone) | `edits.json` `title` | `edits/cover.jpg` + `cover` | `characters` | `chapters` | `music` |

A book with a workshop never has `edits.json`. A book without one never has the sidecars. The book layer (`book.json`,
`cast.json`, `scripts/`, `cover.jpg`, music, audio) is never modified in place.

## `edits.json` (version 1)

```
{"format": "abook-edits", "version": 1,
 "title": "Tên mới",                        absent = unchanged
 "cover": null | {"color": "#aabbcc", "width": 96, "height": 128, "version": 1759400000},
                                            absent = unchanged; null = no cover (drawn from the title);
                                            object = use edits/cover.jpg (version = cache-buster the writer picks)
 "characters": {"<cast.json name>": "<shown name>"},
 "chapters": {"<chapter id>": {"title": "Chương 12", "subtitle": "Hồi kết"}},      each field optional
 "music": {"enabled": false, "levelDb": -24.0, "silenced": ["<chapter id>:<start ms>"],
           "pins": {"<chapter id>:<start ms>": "local:<sha1>"},
           "tracks": {"<sha1>": {"ext": "mp3", "title": "...", "creator": "...", "duration": 184.0, "lufs": -14.2}}}}   each field optional
```

`pins` = a cue the listener switched to one of their own tracks ("Nhạc của tôi", docs/MUSIC_IMPORT.md); `tracks` describes exactly
the tracks the pins name (no more, no fewer - anything else refuses the file): `ext` one of mp3 / m4a / ogg / opus / flac / wav,
`title` / `creator` clean text <= 200 code points when present, `duration` in (0, 1e6] seconds, `lufs` in [-100, 20] (measured
from the file itself). No licence or attribution: the file's own name and artist are all ABook shows. The track FILE sits in the
book folder as `music/<sha1>.<ext>` - the place a producer's own track would be - and `repack` / `BookDocumentWriter` add it to the
file next to the book layer (the book layer's `package.files` is never rewritten; the saved file's list covers it).

Strict (untrusted input - it arrives inside someone else's .abook): only these keys (plus `wishes`, below); size <= 1 MiB; <= 2000 characters,
5000 chapters, 5000 silenced cues, 5000 pins; title/chapter text <= 160 code points, character names <= 80 (the server's
`TITLE_MAX` / `names.MAX_NAME`); text must already be clean (no control characters, no whitespace other than single ASCII
spaces, no leading/trailing space) - validation REFUSES, it never repairs; `levelDb` in [-40, -6]; cover color `#rrggbb` or
"", sizes 0..20000; `edits/cover.jpg` must exist iff `cover` is an object, be a JPEG, <= 8 MiB. Any violation refuses the
whole file. No device names or paths are stored (the only times are the `requested_at` stamps of wishes, see P2a). Writers store the minimum: a value equal to the book layer's is
removed (no-op edits never count), `enabled: true` is never stored.

Counting ("N thay đổi"): title + cover + each character + each chapter + enabled + levelDb + each silenced cue + each pin + each wish (P2a).

## Overlay (what the listener sees)

`apply_manifest(book, edits)`: `title`; `parts[].title` = `"<new title> · Phần N"`; `chapters[]` `title` / `subtitle` /
`fullTitle` (`fullTitle` = `title · subtitle`, or `title` when the subtitle is empty); `cover` -> `null` or
`{file: "edits/cover.jpg", ...cover}`; `music`. `apply_cast`: `displayName` = the edit, `originalName` = the pre-edit original
(`originalName`, else `displayName`) unless the edit equals it; `firstChapter` follows a renamed chapter `title`.
`apply_script`: `speaker` = new display name (scripts store the display name at pack time), `title` = renamed `fullTitle`.
`apply_music`: a pinned cue's `track` becomes `music/<sha1>.<ext>` and `tracks` gains `{file, link: "local:<sha1>", title?,
creator?, lufs?}` (kept when the producer's own book already holds that name); `levelDb` replaces the level and every cue's
`gainDb` is recomputed with `music_plan.cue_gain_db(level, track.lufs, track.speechBand)` (a pinned cue gets its gain from the
level in force even when `levelDb` is not edited); `enabled: false` empties `chapters`; silenced cues are dropped. A cue's key is
`"<chapterId>:<round(start * 1000)>"`.

Merge on re-import, `merge(local, incoming)`: the key present on this device wins, the rest is taken from the file; silenced
cues are a union; pins are a union (this device's pin wins on a cue both pinned) and `tracks` keeps only what the merged pins name.
The pinned track FILES follow: an extract keeps this device's files (`BookFile._keep_local_edits`, `BookFileImport.keepLocalEdits`) and
adopting into a fuller book takes the incoming file's (`book_edits.adopt(..., member)`). Report `{adopted, kept, conflicts, cover: "local" | "incoming" | null}`.

## Routes (same JSON on the Python server and `LocalStudio.kt` for a book without a workshop)

All under `/api/books/<id>`; the server also accepts them for workshop books (same shapes, existing sidecars).

| Request | Response |
|---|---|
| `PUT /title {title}` | `{"title"}` (workshop: the project summary, as before) |
| `PUT /cover {image: dataURL}` (or `{url}`, desktop only) | `{"cover": {color, width, height, version}}` |
| `DELETE /cover` | `{"cover": null}` |
| `POST /characters/rename {character, name}` | `{character, name, original, renamed}` |
| `PUT /chapters/<n>/title {title?, subtitle?, revert?}` | `{chapterId, title, subtitle, fullTitle}` |
| `GET /music` | `{package: true, hasMusic, enabled, levelDb, defaultLevelDb, cues: [{key, chapterId, chapter, start, end, title, creator, silenced, pinned?: true}]}` |
| `PUT /music {enabled?, levelDb?, silence?: {key: bool}, pins?: {key: "local:<sha1>" \| null}}` | the same view; any other key -> 400. A pin copies the track's file from this device's "Nhạc của tôi" into the book folder (400 "Bài này không còn trong Nhạc của tôi" when it is gone); `null` goes back to the producer's track and drops the file |
| `GET /music/scenes/<cue key>/alternatives` | `{key, alternatives: [], mine: [{link, title, creator, attribution: "", duration, analysed, fits: false}]}` - a packaged cue has no mood to score, so only "Nhạc của tôi" (every track but the one in use) is offered; 404 for an unknown cue |
| `GET /api/music/local`, `DELETE /api/music/local/<sha1>`, `POST /api/music/local/analyze` | this device's "Nhạc của tôi" (docs/MUSIC_IMPORT.md) - the phone answers them in `LocalStudio.kt` with the desktop's JSON |
| `GET /edits` | `{applied: N, waiting: 0}` (workshop: `waiting` = edits from a file awaiting "áp vào dự án?") |
| `DELETE /edits` | `{applied: 0, waiting: 0}` |
| `GET /cast`, `GET /chapters/<n>/script` | the overlaid cast / script |
| `POST /save {as?: "abook"}` (desktop) | `{file, folder, size, edits}`; `as: "abookproj"` -> 409 "cần máy có Studio để dựng xưởng" |
| `POST /edits/fold` (workshop only) | `{applied, skipped, music, requests}` (`requests`: wishes turned into pending requests) |

Errors are `{"error": "<Vietnamese sentence>"}` with 400 / 404 / 409 (`ValueError` -> 400).

## Saving and file format v4

`bookfile.repack(folder, out)`: the book layer byte for byte (hashes already known are not recomputed), plus `edits.json`
and `edits/cover.jpg` when there are edits; then `package.version` is 4 (otherwise the lowest version that fits: 1 / 2 / 3).
`package.files` is recomputed over every entry; `manifest.json` (Readium) is regenerated from the overlaid book. Android:
`BookDocumentWriter.write(bookDir, out)` does the same with `ZipOutputStream` (mimetype first and stored, `.mp3` / `.wav` /
`.jpg` stored with CRC). `.abook` v4 rejects `project/`, `sources/`, `views/` (unknown names). "Lưu thành .abookproj" from a
no-workshop book is not built: the UI shows it as a later feature ("cần máy có Studio để dựng xưởng").

Re-importing the same book never wipes edits: `BookFile.extract` merges the folder's `edits.json` with the file's (local
wins); an "existing" book adopts the file's edits in place (`book_edits.adopt`). Android `BookFileImport` does the same.

## Producer fold

Opening an `.abook` that fingerprint-matches one of this computer's projects and carries `edits.json`: the edits are stashed
(`edits_incoming.json`) and `open-book-file` answers `{how: "project", edits: N}`; the UI shows "N thay đổi - áp vào dự
án?" as a toast with an action -> `POST /edits/fold` -> `book_edits.fold` (the existing writers: `store.set_display_title`,
`covers.save_cover_bytes`, `names.set_name`, `store.set_chapter_title`, `music_plan.write_overrides`; silenced cues map back
to scenes by chapter + start; music pins of imported tracks too: `stash_incoming` copies the pinned files out of the opened book into
`edits_incoming_music/`, `fold` imports each into this machine's "Nhạc của tôi" (`LocalMusic.import_file`, same sha1 dedupe,
title/creator from the edit layer when the file has none) and writes the pin for the cue's scenes via `write_overrides`; a pin
whose file is missing / wrong / whose cue is gone is skipped and its reason goes to `reasons`). Nothing is applied without the click; "Bỏ qua" = `DELETE /edits`.

## P2a - wishes (W class) on a book without a workshop

A listener on a book with no workshop (any `.abook`, desktop or phone) can still ask for the edits that need a Studio run.
They are only RECORDED: `edits.json` gets a `wishes` section whose entries have exactly the shapes of `overrides.json`
(`listener_overrides.py`); they are never applied to audio, nor to any text the listener sees. The listener sees
"Đang chờ Studio" marks (cast row: `pendingVoice`; the "Việc đang chờ Studio" list), and "Lưu" / "Lưu thành" carry them.

```
"wishes": {"pronunciations": {"<surface_key>": {"surface", "spoken_form", "requested_at", "replaced"?}},
           "speakers":       {"<stableId>": {"speaker", "text_sha256", "requested_at", "new"?: {"gender"}, "replaced"?}},
           "lines":          {"<stableId>": {"text_sha256", "kind", "emotion", "intensity", "spoken"?, "requested_at"}},
           "voices":         {"<CHARACTER_KEY>": {"preset", "gender", "avoid", "requested_at", "replaced"?}},
           "retakes":        {"<stableId>": {"text_sha256", "requested_at"}},
           "aliases":        [{"alias", "person", "at"}]}                       each section optional
```

Code: Python `abook/webui/book_wishes.py` (validate/merge/count, the writers, `pending_details`, `fold`), Kotlin `BookWishes.kt`
(+ `VietnameseReading.kt`: the syllable validator `spelling` uses). Both read the same fixtures (`edits/wishes*.json`,
`invalid/wishes_*`, `merge/wishes_*`, `contract/wishes_*`, all generated by `tests/book_edits_fixtures.py`).

- **Writers do not copy Studio's logic.** Python builds a temp folder holding `overrides.json` with the current wishes, CALLS the
  real `listener_overrides.request_*` / `withdraw_requests` / `cancel_retake` on it and reads the result back (so the entry shape,
  the "replaced" memory and Hoàn tác are Studio's own; the locked files are untouched). Kotlin re-implements those few writers and
  is held to the same JSON by the contract fixtures (`"$requestedAt#N"` stands for the clock stamped by step N).
- **Same routes, same JSON** (Python server for a package book, `LocalStudio.kt` on the phone): `POST /pronunciation`, `/speaker`,
  `/line`, `/voice`, `/review`, `/characters/merge`, `/chapters/<n>/retake`, `GET /pending-changes`, `POST /pending-changes/withdraw`,
  `GET /wishes` (the reader's per-line view, below);
  `GET /edits` -> `{applied, waiting: 0, wishes}`. Validation uses the script segments (`stableId` + `textSha256`) and `cast.json`
  instead of SQLite; the Vietnamese error sentences are the workshop's. Not on a package: `bracketRule` / `everywhere` (they need
  the analysis database) are ignored; `/review` records only the retake; `/voice` with neither preset nor gender is refused.
- **One click = one change**: `speakers` and `retakes` entries with an equal `requested_at` count and withdraw as one. `count()` =
  applied edits + wishes; `manifest.wishes` (also `listen` JSON `wishes`) says how many of the N are wishes.
- **Untrusted file**: `validate` is as strict as phase 1 (exact keys and types, clean text, caps - 2000 pronunciations / lines /
  voices / aliases, 5000 speakers / retakes - `intensity` 0..3, `requested_at` finite and positive; any violation refuses the whole
  file). `edits.json` stays <= 1 MiB and a writer that would exceed it answers `TOO_BIG` instead of writing a file it could not read.
- **Merge on re-import**: union by entry key, the local entry wins per key, aliases are unioned, and if the union would exceed the
  caps the local wishes alone are kept. There are no tombstones: withdrawing a wish is local only - re-importing a file that still
  holds it brings it back.
- **Producer fold** (`POST /edits/fold` -> `book_edits.fold` -> `book_wishes.fold`): each wish becomes a request through the CALLED
  `listener_overrides.request_*` writers, `requested_at` re-stamped (now + index * 1e-3 per distinct original click, so clicks keep
  their order and the phone's clock skew does not matter), pre-checked with `store.*_request_problem`; the ones that no longer fit
  the project are skipped. Response `{applied, skipped, music, requests}`; the requests then sit in the normal pending list.
- **`GET /wishes`** (same JSON on the Python server and `LocalStudio.kt`; `book_wishes.by_line` / `BookWishes.byLine`; contract case
  `wishes_by_line`): what the reader marks "đang chờ Studio" - `{"pronunciations": [{key, surface, spokenForm, requestedAt}],
  "lines": {"<stableId>": {"speaker"?: {name, shown, requestedAt}, "delivery"?: {kind, emotion, intensity, spoken?, requestedAt},
  "retake"?: {requestedAt}}}}`. `shown` is the name the listener sees (`displayName`, "người kể", or the typed name); nothing is
  checked against the book (a line that is gone is simply never asked for). A workshop book answers it empty (its requests live in
  `overrides.json`).
- **UI** (`ui/src`): on a book without a workshop the cast tab offers "Đổi giới tính" and "Gộp vào…" (`GenderDialog` / `MergeDialog`
  with `waiting`), the book menu shows "Việc đang chờ Studio (N)" (`listen/WishesDialog.tsx`, sharing `PendingList` with
  "Áp dụng thay đổi"), and the producer's fold toast reports `requests`. **Per line**, in the reader (`listen/ReaderScreen.tsx`,
  desktop and phone - the same screen): tap a sentence -> "Sửa câu này" (`listen/LineWishes.tsx`) opens one dialog with who says it
  (`SpeakerMenu`), kind / emotion / spoken text (`DeliveryMenu`), the reading of one word of the line (`EditReading`, picked from the
  line's own words - a book without a workshop has no name list), and retake the line (`POST /review`). These are the very menus of
  Studio's script tab (exported from `studio/ScriptTab.tsx` / `NameReadings.tsx`), so the rules and words are shared; only the write
  differs. A line with something waiting carries a clock mark in the text, and the dialog lists each waiting item with "Bỏ"
  (`POST /pending-changes/withdraw`) under the `WAITING_STUDIO` sentence; speaker and reading toasts offer "Hoàn tác". Greyed, with
  the reason, never hidden: "Nghe thử" and "Dùng cho mọi sách" in the reading editor (they need a workshop / the computer's shared
  list), speaker on a narration line, retake in a chapter with no audio, a line without `stableId` (a file packed by an old Studio),
  and the whole button on a streamed ("link") book (`LINK_BOOK`) or a workshop book without Studio. A workshop book with Studio gets
  "Sửa trong Studio" (desktop: the same line in the script tab). `shared/capabilities.ts`: `lineEditing(caps)` decides which.
  `POST /pending-changes/withdraw` is not propagated through re-import (see above).

## Not built (later phases)

The sync edits inbox, `.abookproj` v2, phone cover web search; swapping a cue to a CATALOG track on the phone (only the listener's
own tracks can be pinned to a packaged book - there is no catalogue offline and no mood to rank by); edits on
streamed ("link") books; an in-place "Lưu" that overwrites the original file (desktop "Lưu" writes `Đã xuất/<title>.abook`,
Android asks where with the system "create document" picker).
